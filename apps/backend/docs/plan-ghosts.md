# 계획 고스트 (Plan Ghosts)

봇이 **"이렇게 놓을 생각이다"** 를 자기 보드에 반투명 미노로 띄우는 기능입니다. AI가 가방 단위로 세운 계획을 사람이 눈으로 볼 수 있게 하는 표시 전용 오버레이입니다.

**게임 상태가 아닙니다.** 시뮬레이션·판정·리플레이 검증 어디에도 끼지 않으므로 결정론을 건드리지 않습니다. 같은 입력이면 계획을 띄우든 안 띄우든 판의 전개와 지문이 동일합니다(테스트로 고정되어 있습니다).

---

## 한눈에

```jsonc
// 통째로 올리기
{ "t": "plan", "set": [
  { "id": "p0", "piece": 6, "rot": 0, "x": 3, "y": 38, "alpha": 0.55 },
  { "id": "p1", "piece": 4, "rot": 0, "x": 0, "y": 36, "alpha": 0.45 }
] }

// 하나만 추가·갱신 (같은 id면 덮어씀)
{ "t": "plan", "add": [{ "id": "p2", "piece": 1, "rot": 1, "x": 8, "y": 34 }] }

// 골라서 지우기
{ "t": "plan", "remove": ["p0", "p2"] }

// 전부 지우기
{ "t": "plan", "set": [] }
```

`relay`로 감싸지 **않습니다.** 제어 메시지로 그냥 보냅니다 — 상태를 서버가 들고 있기 때문입니다.

---

## 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | △ | 이 고스트의 이름. **`remove`로 지우려면 반드시 필요합니다.** 없으면 `set`으로 갈아끼우는 것 말고는 지울 방법이 없습니다 |
| `piece` | ✓ | 엔진 `Piece` 값 (1=I, 2=J, 3=L, 4=O, 5=S, 6=T, 7=Z) |
| `rot` | ✓ | 엔진 `Rot` 값 (0=Spawn, 1=Right, 2=Two, 3=Left) |
| `x` | ✓ | 보드 열 |
| `y` | ✓ | 보드 행. **버퍼 포함** — `Game.py`와 같은 좌표계입니다 |
| `alpha` | | 0~1. 뒤쪽 계획을 흐리게 할 때 씁니다. 없으면 기본값 |

`x`/`y`는 `shapeOf(piece, rot)`의 오프셋이 더해질 기준점입니다. 즉 엔진에서 조각을 놓을 때 쓰는 좌표를 그대로 넣으면 됩니다.

```js
const spot = bestPlacement(game);          // { rot, px, y }
send({ t: "plan", add: [{ id: "next", piece: game.cur, rot: spot.rot, x: spot.px, y: spot.y }] });
```

---

## 연산 세 가지

- **`set`** — 목록을 통째로 교체합니다. `[]`를 주면 전부 지워집니다.
- **`add`** — 붙입니다. 같은 `id`가 이미 있으면 **덮어씁니다**(갱신).
- **`remove`** — `id` 목록으로 골라 지웁니다.

`add`와 `remove`는 한 메시지에 같이 보낼 수 있고, `remove`가 먼저 적용됩니다. `set`이 있으면 나머지는 무시됩니다.

한 사람이 동시에 띄울 수 있는 개수는 **32개**입니다. 넘치면 앞에서부터 32개만 남습니다.

---

## 서버가 알아서 해주는 것

세 가지는 봇이 신경 쓸 필요가 없습니다.

1. **놓인 자리는 자동으로 걷힙니다.** 계획한 칸이 보드에서 전부 메워지면 그 고스트가 사라집니다. 조각을 놓은 뒤 `remove`를 보낼 필요가 없습니다.
   - 판정 기준은 "고스트가 차지한 칸이 모두 비어있지 않다"입니다. 가비지가 올라와 메워진 경우에도 걷히는데, 그때는 계획 자체가 이미 낡은 것이라 그대로 두는 게 맞습니다.
2. **판이 끝나면 정리됩니다.** 매치 종료 시 서버가 모든 계획을 비웁니다. 판 시작 시에도 한 번 비웁니다.
3. **나가면 사라집니다.** 방을 떠난 사람의 계획은 남지 않습니다.

계획이 바뀌면(봇이 보냈든 서버가 걷었든) 서버가 방 전체에 알립니다.

```jsonc
{ "t": "plan-state", "playerId": "p3xk1a", "ghosts": [ /* 현재 상태 전부 */ ] }
```

---

## 어디에서 보이나

| 경로 | 보임 |
|---|---|
| 방의 다른 참가자 | ✓ 실시간 |
| 관전자 | ✓ 실시간 |
| 리플레이 | ✓ 그 시점에 떠 있던 계획이 재생됩니다. 되감으면 그때 상태로 돌아갑니다 |

서버가 판과 **같은 시간축에 녹화**하기 때문입니다. 봇이 리플레이를 제출하지 않아도 계획은 남습니다.

자기 보드에만 그려집니다 — 남의 보드에는 그릴 수 없습니다.

---

## 참조 구현

`apps/backend/examples/bot-runner.mjs`

- `planAhead(game, depth)` — 다음 조각들까지 미리 놓아보며 계획을 만듭니다. 뒤쪽일수록 `alpha`를 낮춰 확정도가 낮다는 걸 눈으로 알 수 있게 합니다.
- `publishPlan(ghosts)` — 직전과 같은 내용이면 보내지 않습니다. 매 프레임 보내면 트래픽만 늘어납니다.
- 새 조각을 잡을 때마다 갱신합니다.

```bash
FETRIS_BOT_PLAN=3 node apps/backend/examples/bot-runner.mjs   # 0이면 끔
```

방 채팅에서 `!bot plan 0~6`으로 바꿀 수 있습니다.

---

## 주의

- **매 프레임 보내지 마세요.** 바뀔 때만 보내면 됩니다.
- **`id`를 붙이세요.** 개별 삭제·갱신이 되고, 무엇보다 같은 계획을 반복해 보낼 때 중복이 쌓이지 않습니다.
- 좌표가 보드 밖이면 그 칸은 조용히 무시됩니다(에러가 아닙니다).
- 계획을 띄운다고 판이 달라지지 않습니다. 실제로 두는 건 여전히 입력으로 해야 합니다.
