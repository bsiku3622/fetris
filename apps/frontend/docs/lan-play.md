# LAN 직결 대전 (오프라인 · 비행기)

인터넷이 없는 환경(비행기 등)에서 **노트북 두 대를 직접 케이블로 묶어** 1대1 대전을 하기 위한 가이드입니다. 데스크톱(Tauri) 앱에서만 동작하며, 웹 버전에는 LAN 메뉴가 보이지 않습니다.

## 동작 원리 (요약)

- 데스크톱 앱은 내부에 **WebSocket 릴레이 서버**(Rust, `src-tauri/src/lan.rs`)를 품고 있습니다. 온라인 대전에서 쓰는 서버와 **같은 프로토콜**이라, LAN에서도 기존 대전 로직이 그대로 돌아갑니다.
- **호스트** 한 명이 앱 안에서 릴레이 서버를 켭니다(`0.0.0.0:47474`). **게스트**는 같은 망에서 호스트의 IP로 접속합니다.
- 게임 로직은 100% 클라이언트(웹뷰)에서 돌고, 서버는 메시지를 중계만 합니다(sender-authoritative). 즉 **두 노트북이 같은 IP 망에 있기만 하면** 인터넷 없이 대전이 됩니다.
- 그래서 핵심은 "두 노트북을 한 IP 망으로 묶는 것"입니다. 케이블로 묶는 방법은 OS 조합에 따라 다릅니다(아래).

---

## 1단계 — 두 노트북을 한 망으로 묶기 (OS 설정)

### Mac ↔ Mac — Thunderbolt Bridge (가장 쉬움)

1. 두 맥을 **USB‑C / Thunderbolt 케이블**로 직접 연결합니다. (충전 전용 케이블 말고 데이터 가능한 USB‑C/TB 케이블이어야 합니다.)
2. 보통 자동으로 **시스템 설정 → 네트워크**에 **"Thunderbolt Bridge"** 인터페이스가 나타나고, 양쪽에 `169.254.x.x` 자가할당 IP가 잡힙니다. 이 상태로 바로 됩니다.
3. 안 잡히면: 네트워크 설정에서 Thunderbolt Bridge를 추가하고, IPv4 구성을 "수동"으로 두 맥에 각각
   - 맥 A: IP `10.0.0.1`, 서브넷 `255.255.255.0`
   - 맥 B: IP `10.0.0.2`, 서브넷 `255.255.255.0`
   로 설정합니다(게이트웨이 비워도 됨).
4. 확인: 한쪽 터미널에서 `ping 10.0.0.2`(또는 상대 169.254 주소)가 응답하면 준비 끝.

### Windows ↔ Windows — Thunderbolt 네트워킹 또는 USB 브리지 케이블

- **Thunderbolt 노트북끼리:** Intel Thunderbolt 드라이버가 설치돼 있으면 두 PC를 TB 케이블로 연결할 때 "Thunderbolt Network" 어댑터가 생깁니다. 양쪽 어댑터에 같은 서브넷 고정 IP(예: `10.0.0.1` / `10.0.0.2`, 마스크 `255.255.255.0`)를 주면 됩니다.
- **일반 USB만 있을 때:** 두 PC를 그냥 USB‑A↔USB‑A로 직결할 수는 없습니다(둘 다 호스트라 충돌). **USB "데이터 트랜스퍼/브리지" 케이블**(내부에 브리지 칩이 있는 전용 케이블)을 쓰거나, **USB‑이더넷 어댑터 2개 + 이더넷 케이블**로 묶는 방법이 확실합니다.

### Mac ↔ Windows — Thunderbolt 4 / USB4 직결 (요즘 노트북이면 케이블 하나로 됨)

예전엔 맥의 Thunderbolt Bridge와 윈도우 Thunderbolt 네트워킹이 호환되지 않아 직결이 어려웠지만, **Thunderbolt 4 / USB4** 세대부터는 OS가 표준 **peer-to-peer USB4 네트워킹**을 지원해 **케이블 한 가닥으로 묶입니다.** (Apple Silicon 맥은 전부 TB 지원, 윈도우는 TB4/USB4 탑재 노트북.)

1. **Thunderbolt 4 케이블**로 두 노트북을 직접 연결합니다. (충전 전용/USB2 케이블 말고 TB4 케이블이어야 합니다.)
2. peer-to-peer USB4 연결이 맺어지고 양쪽에 **`169.254.x.x` 링크로컬 IP가 자동 할당**됩니다(별도 설정 불필요).
   - macOS: 네트워크 설정에 **"Thunderbolt Bridge"** 로 표시.
   - Windows: **peer-to-peer USB4 이더넷 어댑터**(예: "Ethernet 29")로 표시.
3. 그대로 앱의 LAN 호스트/참가로 대전하면 됩니다 — 호스트의 `169.254.x.x` 주소를 게스트에게 알려주거나 "주변 호스트 찾기"를 쓰세요.

> 우리 게임은 초당 수 KB라 대용량 전송 가이드에 나오는 **MTU/점보프레임(9000) 튜닝은 필요 없습니다.** 기본 연결만으로 충분합니다.
> 단, **둘 다 TB4/USB4여야** 합니다. 구형이거나 USB-C가 USB3 전용(비-TB)이면 직결이 안 되니 아래 대안을 쓰세요.

**TB4/USB4가 없을 때의 대안 (모두 인터넷 불필요):**
1. **USB‑C/USB 이더넷 어댑터 2개 + 이더넷 케이블** — OS 조합 무관, 가장 확실. 양쪽에 같은 서브넷 고정 IP.
2. **한쪽 핫스팟(개인용 Wi‑Fi 공유) → 다른 쪽 접속** — 인터넷 없이도 로컬 Wi‑Fi 망 형성(기내 Wi‑Fi 송출 규정은 확인).
3. **초소형 여행용 라우터** — 둘 다 붙이면 OS 무관 동작.

> 요점: 앱은 "같은 IP 망"만 있으면 됩니다. TB4 케이블이든 이더넷 어댑터든 핫스팟이든, **양쪽이 서로 ping되면** 대전이 됩니다.

### 블루투스로도 되나요?

부분적으로만 됩니다. 원리는 **Bluetooth PAN**(블루투스로 IP 망 형성)이라, PAN만 깔리면 앱은 그대로 동작합니다.
- **Windows ↔ Windows:** ✅ Bluetooth PAN 지원 — 페어링 후 "Personal Area Network에 join"하면 IP 망이 생겨 앱이 그대로 붙습니다(앱 수정 불필요). 대역폭은 낮지만(~1-2Mbps) 이 게임엔 충분, 지연은 케이블/Wi-Fi보다 큼.
- **모던 Mac:** ❌ Apple이 **macOS Monterey(12)부터 Bluetooth PAN을 제거**해 최신 맥에선 PAN이 안 됩니다.
- 앱에 자체 BLE 통신을 넣는 것도 이론상 가능하나, 크로스플랫폼 BLE peripheral 지원이 빈약(네이티브 코드 별도)하고 대역폭/지연이 빠듯해 **공수 대비 실익이 적습니다.**

**케이블이 싫다면** 현실적 무선 대안은 Wi-Fi입니다: 한쪽(특히 Windows) 핫스팟이나 초소형 여행용 라우터에 둘 다 접속 → IP 망 → 앱 그대로 동작. (모던 맥은 ad-hoc "네트워크 만들기"도 제거돼 AP 역할은 어려움.)

## 2단계 — 앱에서 대전하기

대전 메뉴(CUSTOM ROOM)의 로비 아래에 **"LAN 직결"** 섹션이 보입니다(데스크톱 전용).

### 호스트 (방 만드는 사람)

1. **"LAN 방 만들기 (호스트)"** 를 누릅니다 → 내장 릴레이 서버가 켜지고 대기실로 들어갑니다.
2. 대기실 왼쪽에 **방 코드**와 **LAN 주소(예: `10.0.0.1:47474`)** 가 표시됩니다. 이 둘을 상대에게 알려주세요.
   - 여러 IP가 보이면, 상대와 묶인 케이블/어댑터의 IP(보통 `10.0.0.x`, `192.168.x.x`, 또는 `169.254.x.x`)를 알려주면 됩니다.
3. 상대가 들어오면 **"대결 시작"** 을 누릅니다.

### 게스트 (참가하는 사람)

1. 로비 LAN 섹션에서 **"주변 호스트 찾기"** 를 누르면 같은 망의 호스트를 자동 탐색해 IP 칸을 채워줍니다.
   - 자동 탐색이 안 되면(브로드캐스트 차단 등) 호스트가 알려준 **IP:포트**를 직접 입력하세요.
2. 위 **"방 코드"** 칸에 호스트가 알려준 코드를 입력합니다.
3. **"LAN 참가"** 를 누릅니다 → 대기실 입장 → 호스트가 시작하면 대전 시작.

## 문제 해결

- **연결이 안 돼요**
  - 먼저 OS 수준에서 서로 **ping**이 되는지 확인하세요(1단계). ping이 안 되면 앱 문제가 아니라 망 구성 문제입니다.
  - 호스트와 게스트가 **같은 서브넷**인지 확인(예: 둘 다 `10.0.0.x`).
- **"주변 호스트 찾기"가 비어 있어요**
  - 일부 환경은 UDP 브로드캐스트(`47475` 포트)를 막습니다. 이때는 호스트 IP를 **직접 입력**하면 됩니다.
  - 호스트가 **먼저** "LAN 방 만들기"를 했는지 확인(비콘은 서버가 켜져 있을 때만 나갑니다).
- **방화벽**
  - 호스트 쪽 OS 방화벽이 켜져 있으면 앱(또는 포트 `47474` TCP / `47475` UDP)의 인바운드를 허용해야 합니다. macOS는 첫 실행 시 "들어오는 연결 허용" 팝업이 뜨면 허용하세요.
- **포트 충돌**
  - `47474`가 이미 쓰이면 앱이 자동으로 임의 포트로 바꿉니다. 그땐 대기실에 표시된 **실제 포트**(예: `:51234`)를 그대로 게스트에게 알려주세요.

- UI: `src/ui/VersusScreen.tsx` 로비의 LAN 섹션
- 프로토콜은 온라인 릴레이(`backend/src/protocol.ts`)와 동일 — 같은 `NetClient`/`Transport`가 LAN/온라인 양쪽에서 그대로 동작합니다.
